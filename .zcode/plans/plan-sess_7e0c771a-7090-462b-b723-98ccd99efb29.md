# แผน: ปรับปรุงหน้านักศึกษา (LIFF shell + กิจกรรม/ประวัติ/โปรไฟล์) + แจ้งเตือน plain text เมื่อเช็คชื่อซ้ำ

## การเบี่ยงเบนจากเอกสารที่ต้องแจ้ง (ตาม AGENTS.md)

1. **Design doc §6.1** เดิมระบุ liff layout "ไม่มี sidebar" → เปลี่ยนเป็น **header bar + แถบเมนูล่าง (bottom nav)** ตามคำขอเจ้าของโปรเจกต์ (เหมาะกับจอมือถือ LIFF มากกว่า drawer) — จะอัพเดต design doc ให้ตรงความจริง
2. **สเปก §21/§52/§63** หน้า "กิจกรรม" ของนักศึกษาเป็นเฟสถัดไป → **ดึงมาทำตอนนี้** ตามคำขอ โดยใช้ endpoint `GET /me/activities` ที่สเปก §35 จองชื่อไว้พอดี
3. **แจ้งเตือนกรณีเช็คชื่อซ้ำ** เป็น scope ใหม่ที่สเปกไม่ได้กำหนด (§64.3) — ไม่ขัดกฎใด (§17/§55 ห้ามแค่สร้าง attendance ซ้ำ, §42 ห้ามแค่ส่ง *success message* ซ้ำ) แต่จะใส่ cooldown ตามเจตนา §42

---

## ส่วนที่ 1 — API: แจ้งเตือน "เช็คชื่อกิจกรรมนี้ไปแล้ว" (plain text)

ระบบแจ้งเตือนทั้งหมดเป็น plain text อยู่แล้ว (`{ type: 'text' }`) ไม่มี flex ในโค้ด — ข้อความใหม่เป็น plain text อัตโนมัติ

1. **`line-messages.ts`**
   - เพิ่ม `ALREADY_CHECKED_IN` ใน `NOTIFICATION_TYPES`
   - เพิ่ม `alreadyCheckedInMessage(activityName, checkInAt?)` — ข้อความไทยรูปแบบเดียวกับ `checkinSuccessMessage` เช่น `ℹ️ คุณเช็คชื่อกิจกรรมนี้ไปแล้ว\nกิจกรรม: X\nเวลา: 22:06 น.` (บรรทัดเวลามีเฉพาะเมื่อรู้เวลาเดิม) — ใช้ helper ฟอร์แมตเวลา th-TH Asia/Bangkok ร่วมกับ success message

2. **`beacon-event.service.ts`** — branch ซ้ำ 2 จุด ปัจจุบันเงียบ:
   - ทางเข้าหลัก (`existing` เจอ attendance แล้ว): เพิ่ม `checkInAt` ใน `select` แล้วเรียก `notifications.send({ studentId, lineUserId, type: 'ALREADY_CHECKED_IN', message: alreadyCheckedInMessage(activity.name, existing.checkInAt), replyToken: replyTokenOf(log), activityId: activity.id })`
   - ทาง unique-race catch (แพ้ race สร้างไม่ได้): เรียกเหมือนกันแต่ไม่มีเวลา (`checkInAt` ไม่มี)
   - **ไม่ต้องแก้ `line-notification.service.ts` เลย** — type ใหม่ได้ cooldown bucket ของตัวเองอัตโนมัติ (per student+type+activity) ตาม §42, ส่ง reply ก่อน push แล้ว, ล้มเหลวไม่กระทบ attendance, บันทึกแถว notifications ตาม §20
   - `processing_status` คงเป็น `DUPLICATE` (ไม่เพิ่ม status ใหม่ — ระบบ cooldown/status แยกกันตามตารางของสเปกอยู่แล้ว)

3. **อัพเดต/เพิ่ม tests ใน `attendance-engine.spec.ts`** (pattern เดิม: override `LINE_MESSAGING_CLIENT`, seed, `postEvents` + `drain()`):
   - แก้ test duplicate เดิม (ตอนนี้ pin ไว้ว่าเรียก reply ครั้งเดียว) → คาดหวัง 2 ครั้ง: success ตามด้วยข้อความ ALREADY_CHECKED_IN + แถว notifications `{ type: 'ALREADY_CHECKED_IN', status: 'SENT', activityId }` + attendance ยังเป็น 1 แถว
   - เพิ่ม test cooldown: event ซ้ำครั้งที่ 3 ภายในหน้าต่าง cooldown → มีแถว SENT ของ type นี้แค่แถวเดียว

## ส่วนที่ 2 — API: endpoint ข้อมูลกิจกรรมสำหรับนักศึกษา

4. **`me.controller.ts`** (`@Public()` + `LineAuthGuard` เหมือน endpoint เดิม):
   - `GET /me/activities?page&pageSize` — กิจกรรม **PUBLISHED เท่านั้น** เรียง `startAt` แบบใหม่สุดก่อน, คืน `Paginated<MyActivityItemDto>`: `{ id, name, description, location, startAt, endAt, checkinOpenAt, lateAt, checkinCloseAt, timeState, myAttendance: { checkInAt, status, checkinMethod } | null }` — `timeState` คำนวณฝั่ง server ด้วย logic เดียวกับ ActivitiesService (extract ใช้ร่วม), `myAttendance` merge จาก query เดียว
   - `GET /me/activities/:id` — PUBLISHED เท่านั้น (DRAFT/CANCELLED → 404 เพื่อไม่เปิดเผยข้อมูล), คืน item เดียวรูปเดียวกัน
   - Unlinked ผู้เรียกได้ (ข้อมูลกิจกรรมไม่ใช่ข้อมูลส่วนตัว, `myAttendance = null`), ยึด §54.14 นักศึกษาเห็นเฉพาะข้อมูลตัวเองเสมอ
   - Implement ใน `line-link.service.ts` ตาม pattern `getMyAttendances`

5. **tests ใน `line-link.spec.ts`** (pattern เดิม: override `LineTokenService.verifyIdToken` + supertest): list มี items + myAttendance merge ถูก, detail 404 เมื่อ CANCELLED, unlinked ได้ `myAttendance: null`

6. **`pnpm gen:api`** regenerate `openapi.d.ts` ฝั่ง web (Decision D5)

## ส่วนที่ 3 — Web: LIFF shell + หน้าใหม่

7. **`composables/useLiffSession.ts`** — extract bootstrap ที่ copy-paste กันอยู่ (watch status → ID token → `GET /me`) จาก register/profile มาเป็น composable เดียว: `{ status, sessionToken, me, linked, ensureSession, reloadMe }` — ทุกหน้าใช้ตัวนี้

8. **`layouts/liff.vue`** ออกแบบใหม่:
   - **Header bar บน** (sticky): โลโก้ `lucide:radio` + ชื่อระบบ + avatar (จาก `me.line.pictureUrl` หรือ fallback `lucide:circle-user`) ลิงก์ไป /liff/profile
   - **Bottom nav ล่าง** (fixed, 3 รายการ + active state + aria-label): กิจกรรม (`lucide:calendar-days` → /liff/activities), ประวัติของฉัน (`lucide:clipboard-check` → /liff/history), โปรไฟล์ (`lucide:circle-user` → /liff/profile) — ใช้ semantic tokens (`bg-default`, `border-default`, `text-primary`) ตาม skill web-ui-coding-standards
   - เนื้อหายัง `max-w-md mx-auto` + เผื่อความสูง bottom nav

9. **หน้าใหม่/ปรับปรุง** (ทุกหน้าครบ 3 state: loading/empty/error ตาม pattern เดิม + ภาษาไทย + เวลาเป็น Asia/Bangkok):
   - `/liff/index.vue` — redirect ไป `/liff/activities` (pattern เดียวกับ root → /dashboard)
   - `/liff/activities.vue` — รายการกิจกรรม: การ์ดกดได้ (ชื่อ + StatusBadge timeState + ช่วงเวลา + สถานที่ + badge "เช็คแล้ว" ถ้ามี myAttendance), empty = "ยังไม่มีกิจกรรม", pagination แบบปุ่ม "โหลดเพิ่ม" (pageSize 10), ผู้ยังไม่ลิงก์ → redirect /liff/register
   - `/liff/activities/[id].vue` — รายละเอียด: ปุ่มกลับ + ชื่อ + StatusBadge, description, `<dl>` info rows (สถานที่ / เริ่ม–สิ้นสุด / ช่วงเช็คชื่อ / เกณฑ์มาสาย), การ์ด "การเช็คชื่อของฉัน" (StatusBadge + เวลา + วิธี) หรือข้อความ "ยังไม่ได้เช็คชื่อกิจกรรมนี้", มี state ไม่พบ (404)
   - `/liff/history.vue` — ย้ายประวัติเช็คชื่อออกจาก profile: รายการลิงก์ไปหน้ารายละเอียดกิจกรรมต่อได้ + pagination แบบเดียวกัน
   - `/liff/profile.vue` — เหลือการ์ดโปรไฟล์ + สถานะเชื่อม + ปุ่มยกเลิกการเชื่อม (useConfirm เหมือนเดิม)
   - `/liff/register.vue` — refactor ไปใช้ useLiffSession, พฤติกรรมเดิมทุกอย่าง

10. **`StatusBadge.vue`** — ใช้ตัวเดิม (รองรับ PRESENT/LATE/ABSENT/EXCUSED + timeState UPCOMING/CHECKIN_OPEN/ONGOING/COMPLETED ครบแล้ว), ไม่สร้าง component ซ้ำ
